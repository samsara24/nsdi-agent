# RCA v2 整体思路与实现对齐

本文以 `docs/个人整体思路.md` 为主约束，补充当前实现应如何对齐。目标系统不是强制三分类器，也不是专家规则级联，而是“历史证据图匹配 + 物理约束判关键证据 + 专家 SOP 约束 LLM 推理 + 低置信度降级”的选择性 RCA 流程。本阶段暂不推进 N8 自迭代回灌。

## 端到端链路

1. **N1 证据构建与标准化**：输入一个告警 case，构造 `EvidencePack`，结构性剥离 `label`，记录 observed / missing / not_applicable / invalid 字段状态。
2. **N2 可检视特征抽取**：把遥测转成带物理含义的稀疏 token。特征只负责表达当前 case 的可观察证据，不携带测试标签或历史结论。
3. **N3 证据图历史匹配**：全局图保存 case-vector，用 IDF 加权 Jaccard 做 Top-N；per-case 诊断子图记录 FeatureToken、ConstraintCheck、SOPStep、Outcome 与步骤顺序，用于还原证据链路和归因路径。
4. **N4 分流路由**：路由阈值按当前数据集 train-LOO 标定；路由的职责是决定 N5a / N5b / N5c，不直接替代推理。
5. **N5a 完全匹配**：纯净历史 signature 复用历史确认结论与证据链；混合桶必须降级或交由 LLM 仲裁，不能用多数类硬猜。
6. **N5b 部分匹配**：根据物理约束和量测契约判断缺失/冲突证据是否关键；关键证据缺失或候选冲突时交由 LLM 仲裁，非关键缺失只能降置信复用。
7. **N5c 低匹配/冷启动**：先执行确定性物理排除，再注入专家沉淀的排障 SOP 作为检查顺序，约束 LLM 按步骤推理校验。`learned-sop-v1` / 数值决策树只能作为训练集统计先验，不能冒充专家 SOP，也不能替代 LLM 推理。
8. **N6 置信度与降级**：综合历史覆盖、关键证据完整度、物理约束合规性、SOP 步骤完备性和 LLM 推导缺口，输出 final / request_evidence / human_review。正式默认只接受 branch 候选；expert / learned SOP 只能作为对照或报告字段。
9. **N7 报告生成**：正式实验生成总览 HTML 与逐 case HTML，必须展示主流程图、本轮调整点、路由、历史候选、证据链路、关键证据判定、SOP 步骤、物理约束违规、LLM prompt/原始输出/违规记录、M9 降级原因，以及每个 bad case 的错因。
10. **N8 证据图回灌**：只有人工确认后的 case 可以回灌。本阶段明确不执行 N8 自动反馈或任何自迭代，测试 badcase 不能修改知识包、SOP、约束、阈值、向量或证据图。

## 非自进化正式实验

`scripts/run_offline_sop_llm_experiment.py` 是当前正式入口，固定执行：

1. 只读取 manifest train split，拟合阈值、FeatureModel、历史向量、EvidenceGraph、专家 SOP 资产、训练统计先验、train-LOO 分支与 LLM 标定。
2. LLM 参与训练 case 的约束推理，合规推理链写入 evidence-graph-v2 诊断子图；数据集标签作为训练历史的确认标签保存。
3. 把全部训练知识写入 `knowledge/knowledge_bundle.json`，用内容 hash 校验后从磁盘重新加载。
4. test split 只使用冻结参数做特征抽取、检索、专家 SOP + LLM 推理与 M9 决策；测试标签只在推理结束后计算指标。
5. 运行前用 `nvidia-smi` 检查 GPU；无 GPU 不启动正式实验。结束时显式关闭 vLLM、清空 CUDA cache，并保存运行前后 GPU 快照。
6. 输出 `summary.json`、`run_manifest.json`、`outcomes.json`、`traces.json`、训练知识产物及 `html/index.html` + 逐 case 页面；如果作为 Loop 实验，还必须同步归档到 `experiments/<YYYYMMDD>_<short-name>/` 并生成 `report.html`。

本轮明确不执行 N8 自动反馈或任何自进化：测试 badcase 不能反向修改知识包、SOP、约束、阈值或向量。

## Loop 实验报告门禁

每次 Loop 实验都必须先从测试 bad case 出发提出假设，并且只能围绕证据图约束 / schema、阈值或路由、大模型 prompt、代码 bug fix 这几类核心调整。不得为了刷强制三分类 accuracy 而改动主链路。

实验归档目录固定为 `experiments/<YYYYMMDD>_<short-name>/`，至少包含 `report.html`、`experiment_manifest.json`、`summary.json`、`case_analysis.json`、`bad_cases.json`、`label_suspects.json` 和 `irreducible_cases.json`。其中 `report.html` 必须包含当前主流程图，并标注本轮调整点；`case_analysis.json` 必须保留每个测试 case 的分支、预测、证据链路和分析；`bad_cases.json` 必须逐条说明失败步骤和错因。

正确 case 可以按分支归纳：历史证据链相近、关键证据判断正确、SOP 约束有效、低置信度降级合理等。Bad case 必须逐条分析：如果怀疑 label 错误，写入 `label_suspects.json`；如果基于当前训练集、专家规则、SOP 和测试可见证据都无法安全提升，写入 `irreducible_cases.json`，后续实验继续保留但不再围绕这些 case 反复优化。

## 当前实验边界

- 已实现：EvidencePack、v2 manifest、feature-dictionary-v2、物理/量测/统计分层约束、训练知识包持久化、case-token 图、训练 LLM 诊断子图、测试侧只读加载、SOP+LLM 编排、GPU 生命周期记录和逐 case HTML 报告。
- 仍需实验确认：l2fixed 上的实际专家 SOP + LLM 指标、路由阈值、Top-N、关键证据判定、置信度曲线、多 seed 和 fiber 分层稳定性。
- 仍需外部确认：两端 lane 编号是否物理对应、`serdes_snr` 量纲、blackout 时哨兵值语义、专家 SOP 原文。

## 关键边界

物理约束用于禁止不可能或不可信的推理，并在 N5b 判断缺失证据是否关键；专家 SOP 是 N5c 的检查顺序和推理约束；证据图既保存历史 case-vector，也保存每个 case 的推理链路。`learned-sop-v1` / 数值决策树只能作为数据驱动统计先验，必须报告支持数和 Wilson 下界，不能冒充专家确认规则，也不能默认进入 M9 自动终裁级联。
