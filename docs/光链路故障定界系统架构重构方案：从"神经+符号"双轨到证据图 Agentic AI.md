# 光链路故障定界系统架构重构方案：从"神经\+符号"双轨到证据图 Agentic AI

**核心结论。** 放弃"神经层 \+ 符号层"双轨推理框架，改为以证据图历史匹配为主干、按"已见 / 未见"故障模式分流的 Agentic AI 架构；两周内产出新框架代码、系统架构图与通用物理约束规则，一个月内完成实验与论文投稿。

# 一、背景与目标

本项目面向光网络（光模块 / 光链路）现网故障排查，目标是把新告警或新 case 自动定位到明确故障根因，并给出可解释的证据链与处置建议。8 月 6 日会议正式判定原双轨框架不满足需求，需要围绕陈子昂主导的架构重构重新拉齐一次全链路视图。本文回答三件事：

1. 针对一条输入告警 / case，**当前系统在做什么**——分步骤、可追溯到数据。

2. **目标 Agentic AI 架构**的完整流程，以及每一步的输入、输出、需要的能力。

3. 陈子昂在两周窗口内，为落地这套架构还需要**补哪些模块、做哪些事、按什么顺序推进**。

## 1\.1 会议决定回顾

|决策项|具体内容|
|---|---|
|废弃项|原"神经层 \(LLM\) \+ 符号层 \(决策树 / KG\) "双轨推理框架；决策树无法自迭代、双轨结果几乎无差异、未清洗数据集准确率仅 50% 左右、Fiber 类样本极少无区分度。|
|新方向|基于**证据图 \(Evidence Graph\) 历史匹配**的 Agentic AI 架构，按"已见 / 未见故障模式"分流处理；物理约束、专家排障 SOP 以 prompt 形式注入大模型。|
|论文叙事|研究动机 = 现网络故障研究未针对光模块物理属性做专项优化；核心价值 = 冷启动可复用专家经验，随 case 演化自迭代。|
|必做实验|纯 LLM 无约束基线；Top\-N、置信度阈值、训练集规模 \(50/100/150/200\) 的多维消融。|

# 二、当前流程：原双轨框架下"一条输入 → 报告"的走向

原双轨框架分离线知识建设与在线双轨推理两阶段。离线阶段只做一次或周期性重建，在线阶段是每条新告警都要走的主链路。下图给出针对**单条输入告警**的端到端走向，节点上标注了每一步的输入数据与产出。

## 2\.1 分步骤说明

|步骤|环节|输入|处理逻辑|产出|
|---|---|---|---|---|
|S1|新告警触发|Alarm event（告警时间、设备 ID、端口、类型）|由监控系统或人工上报触发排查|Trigger context 对象|
|S2|多源证据构建|性能指标、链路 / 端口状态、OTDR / 光功率、拓扑与配置、历史处置记录|按时间窗口拉取多源多粒度证据|原始证据集合 \(raw evidence bag\)|
|S3|证据标准化与质量评估|原始证据集合|实体对齐 / 去重、时间对齐、粒度对齐、证据置信评分|结构化证据包 \(evidence pack\) \+ 质量元信息|
|S4a|神经层 \(LLM\) 推理|证据包 \+ KG|KG\-RAG 检索 → prompt 构建 → LLM 生成候选根因 \(Top\-K\)|神经层输出包 \(根因假设 \+ 置信度 \+ 引用证据\)|
|S4b|符号层 \(KG / 决策树\) 推理|证据包 \+ KG \+ IF\-THEN 规则|符号事实导入 → 一致性校验 → 模式匹配 → 评分|符号层输出包 \(根因候选 \+ 匹配规则\)|
|S5|协同 / 置信校准|两路输出包|结果标准化、一致性与互补识别、反证检测、冲突仲裁|最终根因 \+ 证据链 \+ 置信度|
|S6|工单与报告生成|最终根因、证据链|模板化输出、建议动作|排障报告 / 处置工单|
|S7|反馈闭环|人工回填的处置结果|LLM 抽取结构化 → 知识回灌 → 图 / 规则版本更新|KG 增量、规则调整、审计日志|

## 2\.2 现状的核心问题

**价值同质。** 神经层与符号层均强依赖 KG 检索约束，两路输出在实际 case 上差异极小；协同层的仲裁价值随之被稀释，无法体现大模型的独立推理能力，也不符合期刊评审对方法差异化的要求。

**不可自迭代。** 符号层的核心是训练集上的决策树，新增一个 case 就可能触发整树重构；对现网新增故障演化没有增量学习能力。

**数据质量瓶颈。** 现有两个未合并数据集准确率仅 50% 左右，三分类中 Fiber 类样本极少，模型几乎不会预测该类，指标丢失区分度。

**只优化了 1 个 case。** 神经层仅在一个测试 case 上做过 prompt 微调，未做系统性 prompt / RL / SFT，泛化性未验证。

# 三、目标架构：证据图 \+ 已见 / 未见分流的 Agentic AI

新框架把"KG \+ 双轨"降级为背后的知识来源，让主链路围绕**历史 case 证据图匹配 → 分流处理**展开。核心思想是：现网大多数故障模式会重复出现，若能匹配到高相似历史 case，直接沿用其证据链结论；对未见模式，则用物理约束和专家 SOP 做 prompt 约束，让大模型按行业规范推理，每步做合规性校验。

## 3\.1 分步骤说明

|步骤|环节|输入|处理逻辑|产出|
|---|---|---|---|---|
|N1|新告警 / case 触发|Alarm event \+ 关联端口 / 链路上下文|沿用 S1\-S3 的多源证据采集与标准化|结构化证据包 \(evidence pack\)|
|N2|可解释特征向量抽取|证据包|把每项证据映射到**带明确物理含义**的特征维度：电流异常方向、温度异常方向、发光 / 收光功率异常方向、光模块位置、告警类型、拓扑角色…|Case 特征向量 \(可解释、稀疏\)|
|N3|证据图历史匹配|Case 向量 \+ 历史 case 证据图|按 Jaccard 分数取 Top\-N 相似历史 case，并行做证据链校验|Top\-N 候选 \+ 每个候选的相似度、证据覆盖率|
|N4|分流路由|Top\-N 相似度分布|≥ 阈值 A \(100%\) 走完全匹配；A' \< sim \< A \(50%–95%\) 走部分匹配；\< A' \(\<50%\) 走通用排障|处理分支决定|
|N5a|完全匹配处理|命中的历史 case 证据链|直接沿用结论与证据链输出|根因 \+ 证据链 \+ "完全匹配"标签|
|N5b|部分匹配处理 \(已见模式\)|Top\-N 候选 \+ 缺失 / 冲突证据清单|缺非关键证据直接补齐；缺关键证据触发 LLM 仲裁 \(物理约束 \+ 候选证据链\)；LLM 输出候选置信度|根因 \+ 证据链 \+ 置信度 \+ 仲裁记录|
|N5c|低匹配处理 \(未见模式\)|证据包 \+ 物理约束库 \+ 专家排障 SOP|将约束与 SOP 注入 prompt；LLM 按标准流程逐步推理；每步自动跑约束校验；不合规回退或改写|候选根因 \+ 每步合规性痕迹 \+ 置信度|
|N6|置信度决策|N5 输出置信度|高置信度输出结果；低置信度回落到告警端默认策略 \(如"通用排查建议"或人工介入\)|最终根因或降级建议|
|N7|报告生成|根因、证据链、匹配来源|模板化排障报告；区分匹配路径来源 \(完全 / 部分 / 通用\)|排障报告 / 工单|
|N8|证据图回灌|人工确认结果|把本次 case 加入证据图；已见模式覆盖率随 case 增长而提升，通用排障调用占比逐步下降|证据图版本更新、指标监控|

## 3\.2 冷启动与自迭代

**冷启动。** 无充足历史 case 时，N3\-N5b 分支被跳过，全部走 N5c 通用排障；此时物理约束与专家 SOP 保证基础可用效果，不依赖任何训练数据。

**自迭代。** 每一条经人工确认的新 case 都补进证据图，N3 的匹配空间随之扩大，已见模式覆盖率上升，通用排障分支占比下降；这也是论文里"随 case 演化"叙事的直接落点。

# 四、差距分析：陈子昂需要补齐的模块

与原双轨框架相比，Agentic 新框架保留了"证据采集 / 标准化""知识与规则库""结果回灌"三块设施，但把主推理链从"双轨 \+ 协同"整体换成了"历史匹配 \+ 分流 \+ 约束推理"。需要新建或改造的模块如下。

## 4\.1 模块清单

|编号|模块|状态|要点|
|---|---|---|---|
|M1|可解释特征抽取器|新建|定义特征字典 \(含物理含义 / 单位 / 取值域\)；实现证据 → 特征向量映射；输出必须人类可读，避免落到黑盒 embedding。|
|M2|证据图构建 / 索引|新建|把已确认 case 组织成"节点 = 特征 / 证据、边 = 共现 / 因果"的图；提供 Jaccard 或加权 Jaccard 相似度检索。|
|M3|Top\-N 检索与打分|新建|Top\-N 与阈值 A / A' 参数化；输出候选 \+ 缺失 / 冲突证据清单，供分流路由使用。|
|M4|分流路由器|新建|基于相似度分布决定路径 \(N5a / N5b / N5c\)；策略要可配置，便于消融实验。|
|M5|物理约束库|在建|已明确：电流 / 温度 / 发光功率不能一高一低；本端发光低不能对应对端收光高。剩余通用约束由陈子昂用大模型辅助梳理，夏思博审核后统一入 prompt 规则库。|
|M6|专家排障 SOP 库|在建|黄泽舜 / 其桐负责查找现有"指标查看顺序"等 SOP 文档，明日中午前给结论；找不到就下周去茶思屋获取。|
|M7|约束校验器|新建|把 M5 里的约束翻成可执行断言；N5c 里 LLM 每一步推理都要跑一遍，不合规回退 / 重写。|
|M8|LLM 仲裁 / 推理器|改造|沿用现有 LLM 接口，但 prompt 结构改为 *\[约束库\] \+ \[SOP\] \+ \[证据包 / 候选\] \+ \[任务\]*；输出必须带置信度与每步依据。|
|M9|置信度 / 降级策略|新建|定义置信度阈值和"告警端默认策略"；低置信度不硬输出根因，回落到通用排查建议或人工介入。|
|M10|报告生成器|改造|模板要显式区分匹配路径来源；证据链渲染要人类可读，便于运维和论文附录。|
|M11|证据图回灌闭环|改造|把 S7 的规则回灌改为"证据图 \+ 特征字典"的增量更新；记录 case 版本，方便实验回放。|
|M12|实验 / 消融框架|新建|支持切换 Top\-N、阈值、训练集规模 \(50/100/150/200\)；一键跑基线与消融组；结果沉淀为表格 / 图表。|

## 4\.2 需要在架构外补的"细节"

**特征字典冻结。** 一旦 M1 上线，特征字典的增删都会改变证据图相似度分布，必须像 API schema 一样做版本管理，实验记录里要带字典版本号。

**相似度语义解释。** Jaccard 是稀疏可解释相似度，但对多值 / 数值特征有损失。评审时预期会被问是否考虑加权 Jaccard 或余弦；先在 M2 里预留权重接口。

**标签清洗对齐。** 数据合并 \(黄泽舜 / 王雅琪本周完成\) 后，标签体系必须与特征字典一致，否则会拖累 M3 的匹配质量。

**Prompt 规范。** N5b / N5c 的 prompt 模板要固定 \(变量 \+ 顺序 \+ 输出协议\)，方便消融实验只改一个变量；不要每个 case 手写。

**可复现实验记录。** 每次跑实验时保存：证据图版本、特征字典版本、prompt 模板 hash、超参、随机种子；论文附录里要能对到具体版本。
