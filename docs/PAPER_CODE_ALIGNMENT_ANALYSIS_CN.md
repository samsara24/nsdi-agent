# OptSage 论文初稿 与 nsdi-agent 实现的对齐分析报告

分析对象：

- 论文初稿：`OptSage_for_JSAC/`（`main.tex` + `new_src/*.tex` + `table/telemetry.tex`）
- 代码实现：`rca_framework/`、`scripts/`，以及 `AGENTS.md` / `Progress.md` / `Validation.md` /
  `docs/WEEKLY_REPORT_MVP_TO_I5_CN.md` 记录的实测结果

分析时间：2026-08-12。论文侧以当前 tex 内容为准（注意 `new_src/design.tex` 全文处于注释状态，
90 行全部以 `%` 开头，尚未进入编译；本文仍按"设计意图初稿"对待并逐条核对）。

## 0. 一句话结论

**Motivation、问题定义和"证据统一 + 分支推理 + 可追溯解释"的三段式骨架是可以对齐的；
但论文当前把系统能力归因于"多 Agent LLM 神经-符号推理"，而实测证据显示全部增益来自
一份确定性专家方向表、LLM 作定界器显著更差（McNemar p = 0.0117）。这一条不是措辞差异，
是主张与证据相反，必须先解决，否则后面的对齐讨论没有意义。**

除此之外还有 8 处机制级缺口（多 Agent 编排、频繁项集符号层、证据图关系类型、方向性损耗、
syslog 时序特征、主动探测、反例吸收、根因类别体系）和 2 处评估口径不兼容（强制分类 vs 选择性预测、
fiber 作为正常一类 vs 声明不可辨识）。

好消息是：`design.tex` 尚未启用，改写成本几乎为零；且实现侧手里有一批**其他论文很难拿到的实证结论**
（LLM 岗位适配的四次独立测量、方向表消融、可核对性指标），换个叙事反而更硬。

## 1. 对齐度总表

判定口径：

- **A｜可直接对齐**：论文这么写，代码就是这么做的，且有产物支撑。
- **B｜需降级表述**：机制存在，但强度/覆盖面不及论文写法，改措辞即可。
- **C｜实现缺失**：论文写了，代码里没有，需要补实现或删除。
- **D｜与实测冲突**：论文的主张被自己的实验数据否掉，必须改写。

## 2. 可以对齐的部分（论文可以放心写）

### 2.1 Motivation 与 C1、C3 挑战

Intro 对光网络 RCL 难点的刻画——方向性传播导致"同症状多根因"、单点测量不足以定位——
与实现里被证明**唯一有效的知识**（接收类观测指向对端、发送与电口观测指向本端）是同一个物理洞察。
这不仅能对齐，而且是全文最应该被抬到贡献位置的东西（见 §5）。

C1（异构遥测统一为证据）对应 `EvidencePack` + 特征字典，代码侧做得比论文写的还严谨：
标签在构造入口被结构性剥离、`field_states` 显式区分 observed / missing / not_applicable / invalid、
字典 `content_hash` 绑定抽取器。

C3（可验证解释）对应 `report.py` / `html_report.py` / `llm/explain.py`，并且有**机器可判**的实证：
引用 token 真实存在 100%、落在规则依据上 100%、方向陈述一致 100%、未改判 99.07%，编造 token 0 个。
这类"解释可核对率"指标在同类工作里少见，是能立住的贡献点。

### 2.2 三分支自适应路由

Intro 组件 2 写的"匹配历史 / 补物理约束 / 迭代验证新模式"，与 `router.py` 的 N4 分流
（`board-100-70` 与 `coverage-v2` 两套策略）+ N5a/N5b/N5c 三处理器是结构一致的。
唯一要改的是把 N5b/N5c 的阈值口径写对：`coverage-v2` 用的是**证据全覆盖**而非画板上的 70% 相似度
（这一条本身还挂在 `Validation.md` V1 待夏思博拍板）。

### 2.3 稀疏可解释 token 而非黑盒 embedding

论文强调"把 LLM 限制在图原语上，而不是自由文本"，实现里对应"特征必须是稀疏、可解释、
带物理含义的离散 token，token 的字符串形式就是它的解释"（`features/dictionary.py` 模块头）。
这条对齐得很好，且是 prompt 可控性与解释可核对率能达到 99% 的直接原因，值得在论文里显式建立因果。

### 2.4 弃权与三态出口的雏形

论文 design 里提到 conflict 时"无可判别探测则停止"，实现把这件事做成了正式出口：
`final` / `request_evidence` / `human_review` 三态，且用目标选择性风险反解工作点。
论文目前没写这一层，但它是实现里最成熟的部分之一，补上即可对齐。

## 3. 不能对齐的部分

### 3.1 第一级：叙事与证据相反（必须改，不改会在评审复现时崩）

**问题：** 论文从标题（"agentic AI system"）、intro 三组件、到 design 的神经层/符号层/协调层，
整条叙事把定位能力归给 LLM Agent。实现侧四次独立测量都指向相反结论：

| 岗位 | 测量 | 结果 |
|---|---|---|
| 定界器 | 与专家规则配对（48 条） | 专家对 38、LLM 对 29，LLM 只赢 1 条，McNemar **p = 0.0117** |
| 自我可靠性 | 约束合规 vs 结论正确 | 无关联（p = 0.15 / 0.70），通过组数值上还更低 |
| 质疑器 v1 | 质疑命中率 | 107 条全部质疑，命中率恒等于错误率，lift 为 0 |
| 质疑器 v2 | 质疑强度 vs 判错 | r = −0.155，**p = 0.108**，命中率随质疑强度单调下降 |

且迭代 3 端到端接入 LLM 后，最终数字与不接 LLM 的门禁**完全一致**：
覆盖率 95.33%、给结论精度 76.47%、lift +12.75pp 全部来自 `expert.py` 的方向表，
其中 expert 候选答 90 条、SOP 答 10 条、branch 答 2 条。

**影响：** 如果按现稿投出去，评审只要问一句"LLM 消融掉之后掉多少"，答案是"不掉"。
这不是能靠措辞遮掩的问题。

**处理：** 见 §5 的改写方案。核心是把 LLM 从"判断者"改成"解释者"，
把专家方向表从"背景知识"提到"贡献"。

### 3.2 第二级：机制缺失（论文写了、代码没有）

按补齐代价从低到高排：

1. **证据图关系类型（#5、#6）。** 论文写了 attributable-to / belongs-to / precedes 和负证据实体，
   代码里一个都没有。补齐代价中等：`belongs_to` 其实就是现有二部边换个名字；
   `attributable_to`（观测 → 可归属段）实际上被 `expert.py` 的方向表隐式实现了，
   把它显式化成边是**顺理成章且论文上很好看**的一步；`precedes` 依赖 syslog，见下条。

2. **syslog 时序特征（#9）。** 论文写得很具体（6 小时窗、flap 次数、两端对称性、终态），
   代码里完全没有，且数据侧有硬限制：告警只有 3 种、告警端恒为 L2（V12/V13 待黄泽舜确认）。
   **建议直接从论文删除**，除非合并数据集（V10）带来真实 syslog。写了做不出来是硬伤。

3. **主动探测执行（#13）。** 论文写"发起环回/误码测试/对端读数并注入结果重跑"，
   实现只输出清单字符串。这一条**恰恰是 fiber 问题的正解**（fiber 需要 OTDR、端面镜检、
   双向功率标定、换纤复测），但当前既无执行器也无数据。
   **建议降级为"结构化补采请求 + 人工闭环"**，并把它作为 future work / deployment 讨论，
   而不是作为已实现机制。

4. **符号层的频繁项集多视角挖掘（#11）。** 论文写了四个视角 Agent + 最小覆盖聚合。
   实现是浅层决策树 + 手写方向表。这里有两个选择：
   要么改论文（把 learned SOP 老实写成"训练集归纳的浅层可解释树"，这也是 `AGENTS.md` 的强制口径），
   要么补实现（真去做 per-root-cause 频繁项集挖掘）。考虑到 fiber 只有 12 条训练样本、
   L1/L2 的 token 空间上限已被证明在 70–75%，补实现的期望收益很低。**建议改论文。**

5. **反例吸收与知识演化闭环（#16、#17）。** 论文写得最漂亮的一段，实现只有原语。
   而且 `Validation.md` V20 已确认：正式实验**明确不执行**自进化、test badcase 不得反向改知识。
   即论文里的"单调提升"在当前实验协议下是**结构性不可验证**的。
   **建议整段移到 Design 的"设计支持"+ Deployment 的 future work，不出现在贡献列表里。**

6. **多 Agent 编排（#10、#12）。** `AGENTS.md` 第 5.3 节"不做清单"第一条就是
   "不做多 Agent 编排；只做一个主控流程加一组可审计模块"。论文 design 写了至少 8 个 Agent。
   这是项目章程级的冲突。**建议论文改用"模块/角色"而非"Agent"**，
   或者明确定义"Agent = 有独立输入契约与输出协议的可审计模块"，并在文中一致使用。

### 3.3 第三级：口径不兼容（评估章节写不出来）

**问题定义不一致（#18）。** 论文 design 说定位目标是"发送模块 / 光纤 / 接收模块 + 非光根因"，
同一份 design 后文又说"三段：近端 / 远端 / 光纤"，**论文内部就不自洽**；
而实现是 L1（400G 端）/ L2（200G 端）/ fiber 三类，是端点粒度，且没有非光类别。
这必须在 Background 里一次定死，否则 Evaluation 的混淆矩阵无法与 Design 对上。

**fiber 的处理方式（#19）。** 论文把 fiber 当作可正常定界的一段；实现的实测结论是
20 条 fiber 里 12 条只有单端异常、另一端完全干净，在两端对称性视角下与单端故障不可区分，
放宽入口在 train/test 上同向为负。当前策略是声明为不可辨识 → 转补采。
论文如果不写这一条，Evaluation 表里 fiber 那一行就是 0，且没有解释。
**建议把它写成一个正面结论**："我们用可控的弃答换取了 0 次错误的 fiber 猜测，
并给出具体补采项"，配合 §5 的选择性预测叙事。

**评估指标体系（#21）。** 论文 evaluation 骨架是标准的 accuracy / 效率 / 消融 / 可扩展性 / 超参敏感性；
实现的主指标是覆盖率–精度曲线、相对同子集多数类的 lift、平衡召回、弃答有效性、选择性风险。
两者不是详略之别，是**评估范式不同**：前者假设 100% 覆盖强制分类，后者是选择性预测。
另外实现侧还有两条硬性约束必须进论文：目标选择性风险必须 < 多数类错误率 37.4%
（否则"一律报 L2"就是可行解），以及任何精度都必须同时报同子集多数类基线。

## 4. 论文自身需要修的几处

与代码无关，但会影响可信度：

1. **`design.tex` 全文注释未启用。** 90 行全是 `%`，目前编译出来 Design 章是空的。
2. **实体类型自相矛盾**："transmit module / fiber / receive module + non-optical" 与
   "near endpoint / far endpoint / fiber" 是两套定义，出现在同一节。
3. **`tab:telemetry` 与实际使用的指标不一致**：表里有 Current / Voltage / Temperature /
   TrafficIn / TrafficOut，实现里这些要么无类别分离（bias / Voltage / Temperature 已实测），
   要么根本没用（Traffic）；表里反而缺了真正起作用的 host_snr / media_snr / serdes_snr。
   顺带：`serdes_snr` 量纲未知（V8，健康值 6.6e5–8.2e5），论文里只能作二值使用，不能标 dB。
4. **95% / 24 分钟 / 140 集群这组数字**来自华为云与京东云生产统计，与本文用的 268 条数据集
   不是同一来源，需要明确引用，避免读者误以为是本文数据。
5. **`\name{}` 定义为 `\textit{OptSage}` 但 abstract / keywords / conclusion / related work 全空**，
   `reference.bib` 只有 120 字节。这些是进度问题，不是对齐问题，但 `\nocite{*}` 配空 bib 会编译告警。

## 5. 建议：两条路线

### 路线 A（推荐）：改写论文对齐实测

**新的贡献表述：**

> 我们不是在证明 LLM 能做光链路定界，而是在回答"在标签稀缺、遥测受限的生产光网络里，
> 一个可信的 RCL 系统应该把哪部分交给知识、哪部分交给模型、哪部分交给人"。

三个贡献重排为：

1. **可解释证据构建 + 物理归因图。** 异构遥测 → 稀疏可解释 token（版本化、hash 绑定）→
   带方向归属的证据结构。核心知识是一句可证伪的方向表：接收类观测指向对端，发送与电口观测指向本端。
   **消融是现成的、且极强**：方向表整体反转后精度 76.64% → 25.23%（几乎是镜像），
   一律归本端 44.86%、一律归对端 57.01%，去掉告警端解析一字不变。
   这组数字证明"判别力来自方向这一物理关系本身"，不是数据拟合——规则不含任何在本数据上拟合的参数。

2. **带标定的选择性定界，而不是强制三分类。** 三态出口 + 按目标选择性风险反解工作点 +
   分组 Wilson 下界门禁。现成结果：覆盖率 95.33%、给结论精度 76.47%、相对同子集多数类 +12.75pp、
   平衡召回 0.5023、人工介入 1.87%。并且明确报告 fiber 不可辨识 → 0 次错误猜测 + 定向补采清单。
   这里还有一条可推广的设计规则：**风险预算必须紧于多数类错误率**，否则退化解合法。

3. **LLM 的岗位适配：读证据可以，下判断不行。** 把四次独立测量作为一个系统性结论呈现，
   而不是藏起来。落点是解释器岗位：99.07% 四项可核对、编造 token 0 个，
   且该指标**不依赖标签**（判对组 95.12% vs 判错组 96.00%，几乎相同），可直接搬到生产做持续监控。
   同时诚实写出 D10：解释让正确结论可核对，也让错误结论同样可信——它提升可审计性，不提升可靠性。

**还可以附带两条方法论级的贡献**（这两条在同类论文里很少见，价值不低）：

- **D8 的教训**："现有遥测无法判别 X"这类负结论必须连同异常定义一起陈述。
  同一段物理关系在分位数口径下 Wilson 下界 30.0%（与先验 30.4% 无法区分而被否），
  换工程阈值口径后升到 38.7%。被否掉的是证据定义，不是物理关系。
- **D3 的教训**：约束契约做成语法白名单会误杀语义正确的引用（477 条 fatal 里 298 条坏在这），
  改成 `(侧, 指标)` 语义等价类后通过率 15.0% → 56.2%，且未放松任何物理约束。

**代价：** design.tex 重写（本来就没启用）、intro 三组件重述、evaluation 骨架换成选择性预测口径。
估计 2–3 天，且不需要任何新实验——所有数字都在 `artifacts/` 里。

### 路线 B：补实现对齐论文

要补：多 Agent 编排、频繁项集符号层、证据图三类关系、syslog 时序特征、主动探测执行器、反例记忆库。

**不推荐，理由：**

1. 最贵的两项（syslog、主动探测）被数据卡死，不是工程量问题。V10 合并数据集未交付前做不了。
2. 多 Agent 编排与 `AGENTS.md` 章程冲突，且已有证据表明增加 LLM 环节不带来净增益——
   把一个测不出信号的模型拆成八个 Agent，只会得到八份测不出信号的结果。
3. 频繁项集符号层的天花板已被间接测过：v2 token 空间的可辨识平台是 70–75%，
   而专家方向表已经 76.64%。
4. 即使全部补完，第一级冲突（§3.1）依然存在。

### 混合建议

采路线 A 为主，从路线 B 里只挑一项低成本高回报的补：
**把 `attributable_to`（观测 → 可归属段）显式化为证据图的边。**
它现在被 `expert.py` 的方向表隐式实现了，显式化之后：
论文的"证据图"名副其实、方向表变成图上的一等公民、
`checker.py` 的 `allowed_targets` 校验可以直接建立在图上，三处收益一次拿到。
预计 1 天，且不改变任何实验数字（是重构不是改行为）。

## 7. 写作时必须遵守的口径（来自 `AGENTS.md` / `Progress.md` / `Validation.md`）

**禁止宣称：**

- "LLM 做 RCA 提升了 X% 准确率"——增益全部来自专家规则，LLM 定界显著更差。
- "约束校验提高了结论正确性"——合规与正确性测不到关联（p = 0.15 / 0.70）。
- "LLM 质疑器提升可靠性"——v1 完全退化、v2 无信号。
- "解释器提升系统质量"——错误结论的解释同样流畅（判错组 96.00% vs 判对组 95.12%）。
- "70–75% 是遥测的可辨识上限"——那是 v2 token 空间的上限，已被专家规则 76.64% 越过。
- `learned-sop-v1` 不得写成"专家 SOP"，必须写 learned SOP / data-derived SOP。
- 26 条约束全部 `pending_expert_review`，不得当作已确认物理事实。
- l2fixed（161/107）与 legacy organized（126/85）数字不得混表。
- fiber F1 = 0.20（1/6）不得作为方法有效性证据。
- 用 serdes_snr 区分 6 条 blackout 的 83% 不得写进论文（量纲未知，V8）。
- N5b 的 held-out +11.4pp 不可信（样本 39–67 条）。

**必须如实报告：**

- fiber 绝对样本数（train 12 / test 8）。
- 每个精度旁边的同子集多数类基线。
- 目标选择性风险 < 多数类错误率 37.4% 这条约束及其理由。
- 数据集偏差：告警端口恒为 L2、告警仅 3 种、两端 lane 编号对应未确认（V7）、host_snr 缺失 73%。
- 解释器 99.07% 必须与预注册下界 95.33% 同时给出（检查逻辑是看过结果后改的，D5）。

**阻塞项：** V10（合并数据集）阻塞全部规模消融；V1（N4 阈值口径）、V18（Wilson 下界 0.50 / 支持数 10）
在冻结前，论文里的工作点表述都是临时的。

## 8. 结论

论文和实现在**问题定义、证据构建、三分支路由、可追溯解释**这四件事上是对齐的，
骨架不用推翻。真正的分歧只有一个，但它在最中心的位置：**谁在做判断。**
论文写的是 LLM Agent，实现测出来的是专家方向表，而且这个测量做了四次、
用了四种不同的对象和指标、失败方式各不相同、结论一致。

所以答案是：**当前的写作方法论与实现思路不能直接对齐，但可以低成本对齐——
方向是改论文而不是改实现。** `design.tex` 尚未启用，改写窗口正好。
换成"知识决定判断、模型负责解释、系统负责标定与弃答"的叙事之后，
不仅所有数字都对得上，手里那批 LLM 岗位适配的实测结论反而会成为比原叙事更硬的贡献。
