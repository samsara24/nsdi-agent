# 周报：从 MVP 到迭代 5 的调整、收益与缺陷

覆盖范围：2026-08-07（MVP 正式实验）至 2026-08-12（迭代 5）。
数据集与划分全程不变：`rca_v2_l2fixed`，manifest train/test = 161/107，
测试集只提供无标签触发率，不提供证据图、历史向量或标签。
模型全程为 DeepSeek-R1-Distill-Qwen-32B，seed 42，TP=2。

---

## 一句话结论

**系统效果显著改善，但增益的来源不是模型侧的任何改动，而是这一轮注入的人工专家经验。**
覆盖率 0% → 95.33%，给结论时精度 76.47%，相对多数类的增益从 +1.4pp 提到 +12.75pp，
人工介入 33.64% → 1.87%。四次独立测量表明，32B 模型在本任务上
不能提供任何形式的「判断」，它唯一站得住的岗位是把规则的依据翻译成人话。

## 一、起点：MVP 的状态（2026-08-07）

| 指标 | MVP |
| --- | ---: |
| 自动结论覆盖率 | **0.00%** |
| 人工介入 | 36 条（33.64%） |
| 请求补采 | 71 条 |
| 平衡召回 | 0.00 |
| 弃答有效性 | 0.3458 |

MVP 的工程闭环是完整的（知识包先存后载、无 test 回灌、逐 case 审计页），
但没有任何标定分组同时达到 Wilson 下界 0.5 与支持数 10，M9 因此拒绝了全部结论。
LLM 侧 73 条 trace 累计 599 条约束违规，最高频是把中性护栏当 support（181）
与 token 家族错配（175）。

结论：**工程可用，算法不可用。**

## 二、逐轮调整与收益

### 迭代 1：门限校准 + SOP 进级联（`artifacts/i1_offline_sop_llm_risk035/`）

调整：按目标选择性风险 0.35 在 train-LOO 上拟合门限；把学习到的 SOP 加入候选级联；
把 `fiber` 声明为不可辨识标签，命中即转补采。

收益（表面）：覆盖率 0% → 66.36%，人工介入 33.64% → 6.54%，给结论时准确率 70.42%。

**但这个成绩当时就被自己的指标否掉了**：在被保留的同一批 71 条上，
一律报多数类 L2 就有 69.01%，系统只多对 1 条（**lift +1.41pp**）；
平衡召回 0.2596，低于随机猜一类的 1/3；71 条自动结论里 59 条来自 SOP。
覆盖率的提升几乎全部来自「把多数类机器接进级联」。

两处是实质进步：弃答有效性 0.3458 → 0.5278（人工介入第一次用在了会错的地方）；
8 条 fiber 全部转成带具体补采项的请求，而不是像 MVP 那样预测 10 次只对 1 次。

> 该轮的门限 0.4104 与 66.36% 覆盖率**已作废**，见迭代 2。

### 迭代 2：发现置信度反序（`artifacts/i2_offline_sop_llm_risk040/`）

调整：把置信度标定从留一法改为折外（out-of-fold）；启用按类别校准。

**这一轮的价值是发现了一个会使前面所有工作点失效的缺陷**：SOP 叶内的置信度与正确性
是**反序**的——置信度越高越容易错。迭代 1 的 66.36% 覆盖率因此是在一个错误排序上
标定出来的，修正后同样的 0.35 目标风险只剩 8.41% 覆盖。

修正后重跑，lift +1.39pp、平衡召回 0.2596，与迭代 1 实质相同。
同时得到一条可推广的设计规则：**风险预算必须紧于多数类的错误率**，
否则「一律报多数类」本身就是可行解（本数据多数类错误率 37.4%，
把目标风险设成 0.40 等于在约束里默许退化解）。

LLM 侧 79.5% 的回答被约束校验判废，其中最要紧的一类是**归因方向错误**：
C16 说「某侧出现接收症状时指向对端的发送链路」，模型却写成
「L1 的接收异常 → 支持 L1」，把接收侧症状归给了报症状的那一端。

### 迭代 3：注入人工专家经验（`artifacts/i3b_offline_expert_v3_risk035/`）

调整：把 `docs/EXPERT_EXPERIENCE.md` 的阈值表、异常级别、故障模式优先级与两端裁决
实现为 `rca_framework/expert.py`，并从四个位置接进系统——
M9 候选级联新增 `expert` 候选源；特征字典 v3 = v2 + 专家 token；
约束库升 v6（新增 C23–C26 方向约束）；prompt 升 v7（方向表提到系统 preamble 最前）。

**收益（本项目至今最大的一次）：**

| 指标 | 迭代 2 | 迭代 3 |
| --- | ---: | ---: |
| 覆盖率 | 67.29% | **95.33%** |
| 给结论时精度 | 69.44% | **76.47%** |
| 相对多数类 lift | +1.39pp | **+12.75pp** |
| 平衡召回 | 0.2596 | **0.5023** |
| 人工介入 | 6.54% | **1.87%** |

专家规则单独评测在 test 上准确率 76.64%、lift +14.02pp、L1 召回从 6%~34% 跳到 75%。
规则不含任何在本数据上拟合的参数，**没有可以过拟合的自由度**。

**消融确认增益全部来自「归因方向」这一份知识**（全部在 test 上）：

| 变体 | 精度 | 相对多数类 |
| --- | ---: | ---: |
| 文档原方向 | **76.64%** | **+14.02pp** |
| 方向表整体反转 | 25.23% | −37.38pp |
| 一律归本端 | 44.86% | −17.76pp |
| 一律归对端 | 57.01% | −5.61pp |
| 不解析告警端 | 76.64% | +14.02pp |

反转后精度掉到 25.23%（几乎是原方向的镜像），说明规则在做判别而不是碰运气；
两个「一律归某一端」都低于多数类，说明值钱的是方向表本身；
去掉告警端解析结果一字不变，排除了增益来自 `alarm_ip_interface` 的可能。

方向表本身只有一句话：**接收类观测（rxpower、media_snr）指向对端，
发送与电口观测（txpower、host_snr、serdes_snr）指向本端。**

### 迭代 4：校验器表达能力 + 质疑器（`artifacts/i4_challenge_v1|v2/`）

调整 A（校验器）：新增证据 token 的**语义等价类**——
`level:L1:txpower_mean:low_tail`（分位数）、`drop:L1:txpower:all_lanes`（跌落）、
`expert:L1:txpower:lane_down`（工程阈值）说的是同一侧的同一个指标，契约应共同接受。
拿已保存的 80 条回答离线重放（模型输出一字未变）：
**通过率 15.0% → 56.2%，范围类违规 252 → 95**，且没有放松任何物理约束
（等价类要求 `(侧, 指标)` 完全一致，方向仍由 `allowed_targets` 独立锁死）。

调整 B（质疑器）：把 LLM 从定界器改成质疑器——规则出结论，模型只回答
「哪条前提在本 case 上不成立」。两个版本都失败，见下节。

### 迭代 5：解释器（`artifacts/i5_explain_v1/`）

调整：把 LLM 固定在解释岗位，prompt 明确声明模型**没有改判的资格**；
评测换成四项**机器可判**的可核对性（引用 token 真实存在、落在规则依据上、
方向陈述与方向表一致、未改判规则结论）。

| 检查 | 预注册 | 修正检查后 |
| --- | ---: | ---: |
| 可解析 / token 存在 / token 相关 | 100% | 100% |
| 方向一致 | 96.26% | 100% |
| 未改判 | 99.07% | 99.07% |
| **四项全过** | **95.33%** | **99.07%** |

编造 token **0 个**。两个数都报，因为**检查逻辑是看过结果之后改的**（改动理由见缺陷 D5）。

这项指标不依赖标签：规则判对的 82 条合格率 95.12%，判错的 25 条 96.00%，
两组几乎相同，因此可以直接搬到生产上做持续监控。

## 四、发现的缺陷

### A 类：系统缺陷（已修）

| 编号 | 缺陷 | 影响与处置 |
| --- | --- | --- |
| D1 | **置信度与正确性反序** | SOP 叶内置信度越高越容易错，导致迭代 1 的工作点整体失效。改为折外标定后修复，并新增 `tests/test_confidence_ordering.py` 守护 |
| D2 | **风险预算宽于多数类错误率** | 目标风险 0.40 > 多数类错误率 37.4%，等于在约束里默许「一律报多数类」。已定为硬规则：目标风险必须 < 37.4% |
| D3 | **约束契约是语法白名单** | 校验器按 token 前缀字符串比对，而模型按语义引用，477 条 fatal 违规里 298 条坏在这里。改为语义等价类后通过率 15.0% → 56.2% |
| D4 | **中性步骤无合法出口** | 模型想表达「这一侧正常」时只能挪用中性护栏，被判 fatal。已把此类降为 warning，并在 prompt 里给出合法写法 |
| D5 | **约束命名的对称性诱导伪造** | C23/C24 严格镜像，模型据此推断 C25 也有镜像，凭空写出 `C25_..._on_l2_supports_l2` 共 20 次。我们确实故意打破了对称（L2 侧本端类证据下界 45.5% < 先验 62.1%，只能做成中性的 C26），但命名仍在承诺对称 |
| D6 | **`symptom_side` 是模棱两可的标签** | 模型把「运维在哪端发现问题」当成症状端，与它引用的读数所在侧不一致，导致 3 条物理叙述正确的解释被判错。方向检查改为由每个 token 自己的 `(侧, 指标)` 推出 |
| D7 | **环境：vLLM 必挂** | 本机 NCCL P2P 初始化必挂，需 `NCCL_P2P_DISABLE=1`；自定义 all-reduce 与之同时开启会在注册 cuda graph 后卡死，需 `disable_custom_all_reduce=True`。两者已写进脚本默认值 |

### B 类：方法性缺陷（这些本身就是结论）

**D8：「70~75% 可辨识上限」是 token 空间的上限，不是遥测的上限。**
迭代 2 用三条路线佐证这个平台（精确匹配 73.33%、相似度投票 72.73%、折外 SOP 最纯子集 75.76%），
但三条路线**全部建立在同一个 v2 token 空间里**，一致性不构成独立证据。
专家规则直接读原始 lane 值，test 76.64% 已经越过该平台。

由此得到本项目最可推广的方法论规则：**「现有遥测无法判别 X」这类负结论
必须连同异常定义一起陈述**。同一段物理关系（L2 侧接收症状指向 L1），
在分位数口径下 Wilson 下界 30.0%（与先验 30.4% 无法区分，被 C17 否掉），
换成工程阈值口径后升到 38.7%（明显超过先验）。否掉的是证据定义，不是物理关系。

**D9：LLM 不能提供任何形式的判断（四次独立测量）。**

| 岗位 | 测量 | 结果 |
| --- | --- | --- |
| 定界器 | 与专家规则配对比较（48 条） | 显著更差，McNemar **p = 0.0117**（专家对 38、LLM 对 29，LLM 只赢 1 条） |
| 自我可靠性 | 约束合规 vs 结论正确 | 测不到关联（p = 0.15 / 0.70），通过组数值上还更低 |
| 质疑器 v1 | 质疑命中率 | **完全退化**：107 条全部质疑，命中率恒等于错误率，lift 为 0 |
| 质疑器 v2 | 质疑强度 vs 规则判错 | 测不到关联（r = −0.155，**p = 0.108**），命中率随质疑强度单调下降 |

四次测量的对象、指标、失败方式都不同，结论一致。
同样重要的是它**没有**失败的地方：质疑器 v2 引用的 402 个 token 里只有 3 个不存在（0.7%），
解释器编造 token 0 个，107 条给出 101~103 种不同表述。
**读证据它做得很好，坏的是所有需要下判断的环节。**
这与「LLM 有幻觉」的通行说法不同——幻觉率已经很低，问题在判断力。

**D10：解释让正确结论可核对，也让错误结论同样可信。**
规则判错时，解释一样流畅、一样引用真实证据、一样通过全部检查。
一条真值 L1 被判成 L2 的 case，模型写的是「L1 侧的接收光功率出现异常，但根因在 L2 侧」，
并给出「检查 L2 侧发送光功率」这样的具体动作——措辞、证据、方向推理全都无可指摘，
唯独结论是错的。**解释提高的是可审计性，不是可靠性**，不应作为质量提升对外宣传。

**D11：fiber 召回为 0，且放宽入口是净损失（已测，不必再试）。**
20 条 fiber 里 12 条只有单端 multi_metric、另一端完全干净，
在两端对称性视角下与单端故障不可区分。两种放宽方案在两个切分上同向为负：

| 放宽方案 | 触发 | 真 fiber | 精度 | train Δ | test Δ |
| --- | ---: | ---: | ---: | ---: | ---: |
| 两端都有异常 | 32 | 5 | 15.6% | −4.97pp | −4.67pp |
| 两端有异常且定界不同 | 10 | 1 | 10.0% | −3.11pp | −1.87pp |

**这是补采需求，不是建模需求。**

## 五、尚未解决与下一步

1. **fiber 需要两端之外的信息**：OTDR 曲线、光功率预算差、链路长度、
   同缆其他链路是否同时告警。这是目前唯一确定被数据卡住、而非被方法卡住的地方，
   建议作为下一轮的重点（推动补采而不是继续调模型）。
2. **C26 组可靠性跨切分不稳定**：L2 侧本端类证据在 train 下界 45.5%、test 却有 90.9%，
   相差 27pp，需要更多数据才能定论。
3. **不再设计需要模型下判断的环节**。四次测量已经足够，继续尝试只会得到第五个不显著的结果。

## 六、可复现性

- 全部数字对应 `artifacts/` 下的产物目录，路径已在各节标注。
- `python -m pytest -q` 为 **292 passed**。其中若干条测试专门锁住结论本身，
  例如「方向表反转必须显著劣于多数类」「语义等价类不得跨侧匹配」
  「解释器不得改判规则结论」。
- 校验逻辑的改动一律用离线重放评估，不重复占用 GPU：
  `scripts/replay_constraint_check.py`、`scripts/recheck_explanations.py`。
