主要失败原因

  • 150 条不可辨识：没有异常或关键遥测不足。强制预测准确率 52.67%，本质接近端点先验。
  • logical8 失配：59 条仅命中 25 条（42.37%），旧 LLM 知识与 8×8 拓扑不匹配。
  • 约束没有真正控制生成：280 条出现至少一项校验惩罚；包括约束冲突、无支持步骤、编造证据和量测否决。
  • fiber 几乎失明：14 条 fiber 中建议输出没有命中任何一条；当前证据契约也明确限制仅凭单向遥测判断 fiber。
  • 置信度不可用：更高历史相似度没有带来更高准确率，LLM 自评分和真实正确率未形成单调关系。

优化落地方案

  1. P0：LLM 只做受限仲裁，不做自由三分类。输入必须是物理层生成的候选集、支持/排除矩阵和缺失证据；模型只能排序候选、解释冲突或请求补采，不能创造新候选。
  2. P0：把 checker 前置为解码协议。采用 JSON Schema/grammar；证据 token、约束 ID、effect、target 使用枚举；逐步验证后失败最多重试 3 次。仍失败则 request_evidence，不把修复后的普通文本当终裁。
  3. P0：分开“可推理 gap”与“不可辨识 missing”。263 条 gap 才进入 LLM；150 条 no_anomaly/missing 直接补采。这样避免用多数类伪装覆盖率。
  4. P0：logical4/logical8 分层校准。logical8 当前 42.37%，必须建立 8×8 配对 lane 的方向覆盖率、异常比例和两端 Tx/Rx 一致性谓词，不能复用 logical4 的置信门。
  5. P1：冻结探索性一致门。先在 124 条训练数据上做 LOO/嵌套验证，验证“LLM final ∩ N5c ∩ 物理候选一致”；只有 Wilson 下界和独立验证均达标才增加自动覆盖。
  6. P1：fiber 改为证据获取任务。没有双向同步 Tx/Rx、LOS/LOL、OTDR/换纤或端面检查时不自动判 fiber；让 LLM 输出最小补采集合和端点候选，而非硬猜。
  7. P1：以风险—覆盖曲线验收。分别报告两个来源的 coverage、precision@coverage、constraint-valid rate、retry rate 和 fiber recall；不要用 100% 强制预测准确率代替选择性指标。
